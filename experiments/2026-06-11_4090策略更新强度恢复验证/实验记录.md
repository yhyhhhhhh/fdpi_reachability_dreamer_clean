# 4090策略更新强度恢复验证

## 实验目的

用户在 W&B 中观察到：原始训练约 `1M env steps` 已学会夹取，但 4090 fast 模式接近 `4M env steps` 仍未学会夹取。这说明 fast 过多牺牲了策略学习能力。本实验改用 `configs/reachability_gp_isaaclab22_4090_policy_recovery.yaml`，验证恢复策略、Gp、Gd 与 dual 更新强度后是否能改善夹取学习。

## 实验配置

- 总步数：`10M env steps`
- 并行环境：`NumEnvs=128`
- replay batch：`BatchSize=256`
- imagination batch：`ImagineBatchSize=256`
- 更新触发间隔：`TrainModelEverySteps=512`，`TrainAgentEverySteps=512`
- 更新次数：`ModelUpdate=2`，`AgentUpdate=4`，`Gp/Gd/Dual UpdateSteps=2`
- 性能选项：AMP + TF32，低频日志，replay starts 缓存

## 与 fast 模式的核心差异

fast 模式每 `1024 env steps` 约 `2` 次 agent update；policy recovery 每 `1024 env steps` 约 `8` 次 agent update。该配置仍低于 baseline 的约 `16` 次 agent update，但明显高于 fast，目标是在吞吐和策略学习之间重新折中。

## 运行命令

```bash
bash experiments/2026-06-11_4090策略更新强度恢复验证/运行命令.sh
```

## 重点观察

- `1M env steps` 附近是否恢复夹取行为。
- reward / success / grasp 相关曲线是否明显优于 fast。
- `MainFDPI/entropy` 是否异常塌缩或长期过高。
- `Agent/actor_loss`、`Agent/critic_loss` 是否稳定。
- world model、Gp、Gd、dual loss 是否出现 NaN 或明显崩坏。
- timing 指标下更新部分耗时和整体训练 ETA。
