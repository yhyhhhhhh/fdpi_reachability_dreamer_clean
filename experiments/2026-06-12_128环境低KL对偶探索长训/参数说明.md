# 参数说明：128环境低KL对偶探索长训

## 核心原则

这组实验不是之前的 fast 配置。它只把并行环境数和 batch 提高到 `128`，但保留 baseline 的更新触发频率和更新步数：

- 每 `256 env steps` 触发 world model / agent 更新。
- `ModelUpdate=4`，`AgentUpdate=4`。
- `Gp/Gd/Dual UpdateSteps=2`。
- dual / Gd / Main FDPI 仍延后到 `1M env steps`。

## 运行参数

| 参数 | 当前值 | 含义 | 修改建议 |
|---|---:|---|---|
| `NumEnvs` | `128` | IsaacLab 并行环境数，提高 rollout 并行度和单步 GPU/仿真负载。 | 若 OOM 或 IsaacSim 不稳定，回退到 `96` 或 `64`。 |
| `BatchSize` | `128` | world model / critic replay batch。必须 `>= NumEnvs` 且能被 `NumEnvs` 整除。 | 若显存充足且 GPU 利用率仍低，可下一组升到 `256`。 |
| `ImagineBatchSize` | `128` | agent imagined rollout batch。必须 `>= NumEnvs` 且能被 `NumEnvs` 整除。 | 若策略更新仍偏弱，可升到 `256`，但会增加更新耗时。 |
| `BufferWarmUp` | `51200` | warmup env steps，与 baseline 保持一致。 | 若 128 env 初期数据过短，可试 `102400`。 |

## 训练参数

| 参数 | 当前值 | 含义 | 修改建议 |
|---|---:|---|---|
| `TrainModelEverySteps` | `256` | world model 更新触发间隔，按 env steps 计。 | 不建议放大到 `512/1024`，之前 fast 学习变慢与更新变弱相关。 |
| `TrainAgentEverySteps` | `256` | agent 更新触发间隔，按 env steps 计。 | 保持 baseline 密度，优先观察 1M 前 reward 学习。 |
| `ModelUpdate` | `4` | 每次触发的 world model 更新次数。 | 若 wall-clock 太慢但学习正常，可再做 `3` 的对照。 |
| `AgentUpdate` | `4` | 每次触发的主策略更新次数。 | 当前不降低，避免再次削弱夹取学习。 |
| `DualUpdate.KLCoeff` | `0.1` | 对偶策略 KL 约束强度。 | 观察 dual/main 动作距离和真实危险率后再调整。 |

## 日志参数

| 参数 | 当前值 | 含义 | 修改建议 |
|---|---:|---|---|
| `LogEverySteps` | `8192` | 普通 W&B 日志频率。 | 若需要更细曲线可降回 `4096`。 |
| `TimingLogEverySteps` | `8192` | timing 日志频率。 | 用于判断 128 env 后 GPU 利用率和更新占比。 |
| `SaveEverySteps` | `1000000` | checkpoint 保存频率。 | 长训保留即可，避免频繁 checkpoint 干扰速度。 |
