# baseline工程优化长训

## 实验目的

当前 4090 fast 与 policy recovery 配置虽然提高了吞吐，但 W&B 观察显示夹取学习明显弱于旧 baseline。本实验回到 baseline 的更新密度、batch size 和并行环境数，只保留工程优化，验证学习能力是否恢复。

## 核心配置

- `NumEnvs=64`
- `BatchSize=64`
- `ImagineBatchSize=64`
- `TrainModelEverySteps=256`
- `TrainAgentEverySteps=256`
- `ModelUpdate=4`
- `AgentUpdate=4`
- `Gp/Gd/Dual UpdateSteps=2`
- 工程优化：AMP、TF32、低频日志、timing、replay starts cache、`sample_many`、批量 critic latent encoding、低频 FDPI 梯度诊断。

## 运行命令

```bash
bash experiments/2026-06-12_baseline工程优化长训/运行命令.sh
```

后台 tmux 长训：

```bash
bash experiments/2026-06-12_baseline工程优化长训/启动tmux长训.sh
```

## 重点观察

- `1M env steps` 附近是否恢复夹取行为。
- `Rollout/episode_success_rate` 是否从 0 上升。
- `Train/agent_update_ratio` 是否接近 baseline 更新密度。
- `Timing/*` 是否显示工程优化降低 replay sampling / latent encoding / update 周期耗时。
