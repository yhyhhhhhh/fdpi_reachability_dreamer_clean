# experiment-archive-manager

## 作用

统一科研实验目录结构、命名规范和基础文件，确保实验可追踪、可复现、可检索。

## 适用场景

- 用户要求运行一个新实验。
- 用户要求整理某次实验输出。
- 用户要求建立标准实验目录。
- 用户要求补充实验所需的记录文件。
- 用户要求将零散日志、图片、配置整理为规范实验目录。

## 不适用场景

- 不用于审查算法设计。
- 不用于理论分析。
- 不用于只修改代码但不涉及实验归档的任务。

## 输入

尽量获取以下信息：

- 实验名称。
- 实验目的。
- 运行命令。
- 相关配置文件路径。
- 输出日志位置。
- 是否已有结果图片。
- 是否已有实验目录。

如果部分信息缺失，应先使用已有信息创建基础结构，再在文件中注明待补充项。

## 命名规则

实验目录命名默认采用：

```text
YYYY-MM-DD_中文实验名称
```

示例：

- `2026-06-09_验证新版本训练稳定性`
- `2026-06-10_对比不同配置下的实验结果`

## 标准目录结构

每个实验目录应尽量包含：

```text
experiments/YYYY-MM-DD_中文实验名称/
  实验清单.yaml
  运行命令.sh
  配置.yaml
  参数说明.md
  配置快照/
  代码变更.patch
  指标结果.json
  实验记录.md
  图片/
  日志/
  检查点/
```

## 操作流程

1. 确定实验名称与日期。
2. 在 `experiments/` 下创建实验目录。
3. 创建标准子目录与基础文件。
4. 如果命令参数较多，应配合 `experiment-command-manager` 创建 `运行命令.sh`、`配置.yaml`、`参数说明.md`。
5. 将运行命令入口写入 `实验清单.yaml`。
6. 如果有配置文件，则复制或记录到 `配置快照/`。
7. 如果当前工作区有相关代码修改，则尽量生成 `代码变更.patch`。
8. 如果已有图片、日志、指标文件，则整理到对应目录。
9. 创建或初始化 `实验记录.md`。
10. 提醒或继续调用其他 skill 完成实验记录撰写与长期索引更新。

## 完成标准

- 实验目录已创建。
- 必要文件存在。
- 子目录结构清晰。
- `实验记录.md` 已初始化。
- 如有长命令，已拆分为脚本、配置和参数说明。

## 输出要求

完成后至少输出：

- 新建或整理的实验目录路径。
- 已创建的文件清单。
- 还缺少哪些信息。
- 是否建议继续更新 `EXPERIMENT_INDEX.md`。

## 禁止事项

- 不要创建英文缩写风格且难以理解的实验目录名，除非用户明确要求。
- 不要省略 `实验记录.md`。
- 不要把图片、日志、配置快照全部堆在根目录不分类。
- 不要进行与当前任务无关的算法理论扩展。
