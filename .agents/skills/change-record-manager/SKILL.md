# change-record-manager

## 作用

统一维护项目修改记录，确保每次重要变更都有清晰留痕，并区分修改类型。

## 适用场景

- 代码修改。
- 配置修改。
- 实验脚本修改。
- 修复 bug。
- 调整逻辑。
- 重构目录、模块或接口。

## 不适用场景

- 不用于撰写实验结果报告。
- 不用于维护实验索引。
- 不用于理论正确性分析。

## 维护文件

- `docs/research/CHANGELOG.md`

## 修改分类

记录时必须选择以下一种分类：

- `BUGFIX`
- `LOGIC_CHANGE`
- `REFACTOR`
- `CONFIG_CHANGE`
- `EXPERIMENT_ONLY`

## 记录结构

每条记录建议包含：

- 日期。
- 类型。
- 标题。
- 修改内容。
- 修改原因。
- 影响。
- 验证方式。
- 相关实验（如有）。

## 操作流程

1. 判断本次修改类型。
2. 在 `CHANGELOG.md` 中新增对应条目。
3. 用中文简洁说明本次修改。
4. 如果相关实验已存在，补充实验目录路径。
5. 如果是 bugfix，应明确写出“问题表现、原因、修复方式”。
6. 如果是逻辑修改，应明确写出“行为变化或预期影响”。

## 输出要求

- 修改分类。
- 已写入的 changelog 条目摘要。
- 关联的文件或实验目录。

## 禁止事项

- 不要将多种修改类型混成一类。
- 不要只写“修复了一些问题”这类模糊表述。
- 不要漏写影响与验证方式。
- 不要使用英文长段描述，默认中文。
