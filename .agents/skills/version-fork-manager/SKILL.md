# version-fork-manager

## 作用

在出现较大修改时，帮助创建新的独立版本结构，避免新版本隐式依赖旧版本。

## 适用场景

- 用户明确要求创建新版本。
- 当前修改较大，不适合继续在旧版本上堆叠。
- 需要独立比较新旧版本。
- 需要新版本对应独立实验目录、独立配置、独立入口。

## 不适用场景

- 不用于日常小修小改。
- 不用于单次参数调整。
- 不用于理论审查。

## 要求

新版本应尽量具备：

1. 独立目录。
2. 独立入口文件。
3. 独立配置。
4. 独立实验输出目录。
5. 独立版本名或运行名。

公共代码应放入显式共享模块，如：

- `common/`
- `utils/`

## 操作流程

1. 确认新版本命名。
2. 建立新版本目录。
3. 复制或重建必要文件。
4. 调整配置路径、输出路径、运行名。
5. 标记需要后续执行版本依赖检查。

## 输出要求

- 新版本路径。
- 新增的入口与配置。
- 与旧版本的关系说明。
- 是否建议执行依赖检查。

## 禁止事项

- 不要创建“看似新版本，实则仍依赖旧版本核心实现”的结构。
- 不要复用旧版本输出目录。
- 不要让新旧版本的实验输出混在一起。
